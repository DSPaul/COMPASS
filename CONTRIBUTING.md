# Which PRs are and aren't welcome

## The following PRs are always welcome:

- Bugfixes
- Security fixes
- Performance improvements
- Open issues tagged with "Help Wanted"

## The following PRs require prior discussion:

- New features
- Refactors

Discussions can be started by opening an issue first or reaching out on discord. 

## The following contributions will be ignored:

- Low effort 'slop' PRs
- Massive 10k lines PRs that are impossible to review

# The PR itself

- All PR's should be made against the dev branch, master reflects the current stable release. 
- They should clearly explain what problem is being solved and how.
- Any relevant issues should be mentioned in the description. 
- When relevant, tests and documentation should be included. 
- Be transparent about which Operating systems the PR was tested on if relevant. 

# AI Stand

Code quality comes first, regardless of whether it was written by a human or an AI. 
However all code should be manually reviewed before submitting a PR, no full vibecoding. 
If you expect me to manually review it, I expect the same from you. 
AI should not be used to write the PR description or any comments in the discussion. I prefer talking to a real person.
